# win2blur 功能差异矩阵 — v2.7 vs v2.8 vs v3.0

> 基线：v2.7 = `38c6228`（tag v2.7 实际指向其前一个 commit `cc297de`，内容几乎相同）、v2.8 = `d4c2f6a`、v3.0 = 当前 HEAD（含后续 hotfix：9580155、17d4f92、c7b183e 等）。
> 来源：`native/src/tray_app.cpp`、`crisp_overlay.cpp`、`acrylic_overlay.cpp`、`profile.cpp/h` 三个版本静态对比 + `git log 38c6228..HEAD`。
> 生成日期：2026-08-08。

## 总览

| 版本 | 文件数 | tray_app.cpp 行数 | 新增核心 |
|------|--------|-------------------|----------|

## 用户视角总结：2.7 → 3.0

**新增（3.0 独有）**
- 逐应用 profile（`[Apps]` 表）：每个应用可独立设置 模式/alpha/半径/tint/鼠标跟随圈，缺省继承全局 —— 这是 v3.0 的招牌功能
- 焦点差异化：失焦窗口自动减弱模糊/wash 到 60%、tint 减半（300ms 过渡），提升多窗口可读性
- 鼠标跟随模糊圈：光标附近高模糊、其余区域普通模糊的 radial mask，1.5s 静止自动淡出
- 可变模糊半径（1-120px）+ 缓存帧引擎：调参数不再闪烁/重捕获
- 崩溃保护：overlay 进程死了 1s 内自动重启，3 次/30s 熔断 + 托盘提示；顺带修了"目标窗口被 dual-hide 卡住隐藏"的幽灵症状
- 多 overlay 场景杀错窗口的 bug 修复（按 PID 定位）

**v2.8 引入、3.0 保留的（相对 v2.7 的新东西）**
- Crisp 保字模式：目标窗口保持 100% 不透明（ClearType 不失效），模糊背景 wash 叠在上方 —— 解决 Acrylic 低透明度时文字发虚的问题
- tint 滑块 0-100（v2.7 是写死的 10% 黑；v2.8+ 默认 0=纯模糊，**首次升级后默认观感会变浅**）
- Acrylic overlay 生命周期大修：任意前台事件重锚 z-order、目标隐藏/最小化时 overlay 跟随隐藏、点击穿透
- AutoFrost 撤销（从列表移除或关闭后自动还原窗口）、800ms 轮询、配置 mtime 热读、单实例、无 UAC 注入、状态行 UI
- 调试日志 `C:\Temp\win2blur_debug.log`

**v3.0 语义改变的**
- tint：从"乘入模糊层"（被 wash 稀释到几乎不可见）改为"独立黑色叠层"——现在 tint=N% 在任何 wash 下都真显示 N% 黑
- 类名匹配：v3.0 大小写不敏感（v2.7/2.8 敏感）
- 配置存储：`[AutoFrost] App_N="exe|cls"` → `[Apps] App_N="exe = mode=.."`，首次 Apply 自动迁移（迁移后无字段应用全部回到"继承全局"）
- 会话文件格式向后兼容，但 v2.7 存的会话（0/-1 语义）在 v2.8+ 恢复时 **overlay 效果丢失**

**用户报告"所有功能基本不可用"时的排查重点（代码级怀疑点）**
1. **风险 A（高）**：`apply_profile()` 把 profile 的 mode 写进**全局** `g_effectMode`——不同 mode 的多个 profile 互相覆盖，全局开关（ALT+↓、Settings 单选、热键透明度）的行为取决于"最后被 AutoFrost 匹配的窗口"，跨窗口不可预测；会话保存的 effect 字段也取全局 mode，重启后窗口可能按错误模式恢复
2. **风险 B（中）**：Crisp overlay 的 DDA 初始化失败会 `MessageBox + ExitProcess`——GPU/驱动不支持 Desktop Duplication 的机器上，任何 Crisp 窗口直接弹错误框，且该窗口 overlay 反复崩 → v3.0 崩溃守卫会"3x/30s 熔断"停止重试并弹托盘提示，视觉上就是"效果没了"
3. **风险 C（中）**：v2.7 → v2.8/3.0 升级后，旧 Keep & Exit 会话中的模糊效果全部丢失（透明度还在）
4. **风险 D（低-中）**：启动时 welcome_demo 以 INFINITE 等待阻塞 WM_CREATE——demo 异常挂起时整个应用（热键/恢复/托盘）延迟可用
5. **风险 E（低）**：AutoFrost 预设 `CherryStudio.exe` 在 v2.8 改名 `"Cherry Studio.exe"`（带空格），与真实进程名不符则匹配失效
6. **风险 F（低）**：Acrylic 模糊半径滑块依赖 `injector.exe` + `libfrosted_dwm.dll` 与 exe 同目录；分发副本若缺文件，滑块消失且 radius 走 DWM 默认
7. 热键提示文本三版都仍写 "ALT+DOWN acrylic blur"，在 Crisp 模式下语义已是"wash 开关"（纯文案问题）
